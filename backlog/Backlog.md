## Feature Backlog

### Version 0.1 — Engine, editor, contribution path

Mapping to the development document: T1 = `0.1.a`, T2 = `0.1.b`, T3 = `0.1.c`, T4/T4b = `0.1.d`.

- [ ] **0.1.d — Catalog: one tariff database, client and signed catalog packages (technical part)** *(re-cut 2026-10-31 after the decision for one database with a check state per version; the legal review and the opening to users are outside this item: Research Items "Legal review of the draft texts")*
  - **Model (decided 2026-10-31, internal concept "Eine Tarifdatenbank"):** **one** tariff database with one ID space (`<LAND>/<import|export|grid>/<id>`) and versions (hash, P1). Per version a **check state** (`unchecked`, `checked` with date and source, `released_by_supplier` with date and releasing party, `rejected`), the use status `reliable` (P7) and a lifecycle (`current`, `superseded`, `blocked`, `merged_into <id>`). Trust level for display: released by supplier > checked > reliable > unchecked (derived, not stored). Both views are free, no key:
    - **Catalog:** checked and supplier-released current versions only, as signed package; usable directly
    - **Templates:** all other admitted versions; only opt-in, only copied into the user's own tariffs (`db_ref` keeps the link), never imported as catalog
  - **Done so far:** P1–P6 and the P7 client ([Erledigt](Backlog-Erledigt.md)); publisher exchange (S2), editor status and package download (S3); access key dropped (model change 2026-10-31, in `0.1.12`, not released yet; server side earnie-server TariffDB P5). Server routes 1–4 run on the VPS (earnie-server TariffDB P1/P2)
  - **Builds on Earnie *Edibert P8*:** the public Earnie catalog is a frozen seed and the start of the catalog; packages bring the monthly rates of the reference curves; an import never overwrites monthly rows a user entered without telling
  - [ ] **D1 — `db_ref` without `database`:** `{id, version}` on user tariffs (and later user grid areas). Old files carrying `database` are migrated on load as an explicit format step (decide: `tariff_format` 2 with migration, or a documented loader migration; never silent tolerance). Spec sections 4 and 11, schema
  - [ ] **D2 — Package format 2:** manifest without `database` (one catalog); `edibert_package` 2, format 1 is `PACKAGE_FORMAT_UNSUPPORTED` (no format-1 package was ever published). Content may carry per version `check_state`, `checked_at`, `source`; `build_package` and `verify_package` accordingly
  - [ ] **D3 — Exchange contract v2** (`docs/spec/catalog-exchange.md` first): route 1 `GET /edibert/v1/packages/catalog/latest` (old paths `free` / `verified` removed); route 2 `based_on` for any entry, not only shared ones; route 4 adds `check_state`, `checked_at`, `latest_checked_version`, `merged_into`; new route 5 `GET /edibert/v1/templates` with filters land, direction, grid area (grid fees), supplier search, each version with its status
  - [ ] **D4 — Client:** `ExchangeClient` for routes 1, 4, 5; publisher attribute `catalog` with `check_state`, `checked_at`, `reliable`, trust level and "check overdue" (check interval plus 30 days; for grid fees also when 1 January has passed and the check date is from the year before); editor: status display with the trust level, a template list behind an opt-in (filters as route 5) with "Copy as template", a hint for `merged_into` that re-links the copy only after confirmation; CLI `exchange fetch` without `--database`, new `exchange templates`
  - [ ] **D5 — Server** in earnie-server (TariffDB P6, private): schema, one catalog package, route 5, status fields, moderation commands "check", "record supplier release / withdrawal" (withdrawal falls back to `checked`) and "merge"
  - [ ] **D6 — Docs:** spec (`tariff-format.md` § 11, `catalog-exchange.md`, `api.md`, `publishing.md`), user manuals EN/DE (`cli.md`, `editor.md`, `publishing.md`), `README.md` / `README.de.md`, `catalog/README.md`, `CONTRIBUTING.md` to one database with check states
  - **Acceptance:** a package built offline from the seed and approved shared versions is published on a local server, loaded by publisher and editor, verified and imported; a shared tariff appears as template, is copied, then checked by the server CLI and shows "checked version available" in the copy's status; a supplier release and its withdrawal change the status as decided
  - **Not in 0.1.d:** legal review and opening to users (Research Items), Earnie consent at the pin bump (item "Earnie: share consent and exchange settings" below), simple tariff comparison (own item below), grid areas in the database (`0.1.d2`)
  - **Note:** Edibert and the catalogue are free — donations are highly welcome; regular reminders may appear on running installations
  - **Note:** Use GitHub issues if a concrete tariff can't be modeled with the existing version
- [ ] **0.1.d2 — Grid areas: complete grid-fee model and operator path** *(decided 2026-10-31; spec sections 5a and 5b, Earnie development document "Benutzertarife" kept consistent)*
  - **Decided:** the grid base fee per year belongs to the grid area, not to the supplier tariff. Today an area has only the work price (`base_cent_kwh`), rules and `capacity_charges`; the fixed charge sits in every tariff as `grid_monthly_fee_eur` and has to be typed per tariff
  - **Gap found on AT-VBG** (seed catalog `grid_fees.json`, source note says "not checked against the price sheet"; network operator price sheet valid from 2026-01-01, Netzebene 7): the work price 4.96 / 2.84 ct/kWh and the SNAP window (`AT_NE7`, 20 % off, 3.968 instead of the published 3.97 ct/kWh) are there; missing: grid base fee 54.00 EUR/year (unmetered power), grid loss charge 0.393 ct/kWh, renewables contribution on work 0.583 / 0.364 ct/kWh plus 0.037 ct/kWh on grid loss, renewables flat fee 19.02 EUR per metering point and year; for metered power the power price per kW and year is not modeled at all
  - [ ] **Format:** per area a fixed yearly amount by metering type, and further per-kWh components next to the work price, each with `id` and `label`. Components stay separate because rules such as SNAP reduce only the work price, not the grid loss charge or the levies. Levies set nationally per Netzebene (renewables contribution and flat fee) should be defined once, like `rule_sets`, not copied into every area. Decide: what happens to the tariff field `grid_monthly_fee_eur` (keep for supplier-billed grid fees, or migrate), and whether `tariff_format` changes
  - [ ] **Engine and output:** work price plus components in the slot price (`grid_cent`, with a breakdown in `PriceResult`), the fixed yearly amount as a separate block like the capacity charge (never folded into ct/kWh); `grid_area_version` covers the new fields; invoice check and preview show them
  - [ ] **Data:** check all 14 AT areas against the network operators' price sheets 2026 and complete them (corrections to the seed are allowed under Earnie *Edibert P8*); SNAP as published absolute values per area where the sheet differs from the flat 20 %
  - [ ] **Operator path:** a way for the database operator to create and edit grid areas (an editor view for grid areas with the same checks as on load, or a validated file) and to put them into catalog packages without editing the frozen seed
  - [ ] **Free catalog for grid areas** (decided 2026-10-31: as important as for tariffs, same mechanism as `0.1.d` Catalog P1–P7): users share their own grid area (own values in the grid-fee section, with land, regions, network operator, metering types, components and time windows) to the free database; it reaches other users as a template (opt-in, copy only) and earns `reliable` by use like a tariff
    - Identity and version: `grid_area_identity` / `grid_area_version` exist (`<LAND>/grid/<id>`); the version covers rule set, components and fixed amounts of the new format
    - Origin: `db_ref` on the user grid area, set on "copy from catalog"; the grid-fee section shows "differs from version X" as for tariffs (P3)
    - Sharing client: a grid-area contribution payload with a whitelist (no free text, no meter or consumption data), shown in the share section next to the tariffs with the same preview, opt-out per entry and the share default of the host (P6)
    - Exchange contract (`docs/spec/catalog-exchange.md`): submit route for grid areas (or `direction: "grid"` on the tariff route), `based_on`, the same answer codes; use reports and status queries cover the chosen grid area like the used tariffs (P7)
    - Packages: checked or operator-released grid areas go into `grid_fees.json` of the catalog package, unchecked ones are templates; the import keeps a user's own area untouched (P5)
  - [ ] **Area choice in the stand-alone editor** (decided 2026-10-31): today the editor knows only its own grid fee (`user_house`, `house.json`); grid areas from an imported catalog package cannot be selected, so neither the editor preview nor the publisher uses them. The grid-fee section in the main area offers the catalog areas that match the house land and region, or own values; when no catalog area matches, it says so and asks the user to enter the values. Areas need a `regions` field for this (a federal state can hold several areas, e.g. a city operator or Kleinwalsertal next to the state operator); metering type and quarter-hour meter come from the house capabilities. `house.json` stores the chosen area ID; publisher and preview resolve it like Earnie's `netznutzung`
  - **Note:** Earnie consumes the grid fee (house profile, SE invoice); it follows in its own step after the Edibert release. Its own work price ("Eigener Arbeitspreis") has no time windows while Edibert's own grid fee has; align both
- [ ] **Earnie: share consent and exchange settings** *(moved out of `0.1.d` on 2026-10-31; was step S4; work in the Earnie repository, Earnie backlog "Edibert share consent")*: at the next pin bump Earnie asks for its own consent before any tariff is shared or use is reported, and only then passes an `ExchangeConfig` / contribution transport; no transport without consent
- [ ] **Simple tariff comparison** `[feat]` *(after `0.1.d`; decided 2026-10-31, free lead-in to the tariff comparison in Earnie)*: tariff × standard load profile (e.g. H25) or annual consumption, per slot, for the tariffs of the catalog and the user's own; optional a logged consumption file (takes over the `0.+1` item "vector multiplication"); result as yearly cost per tariff with a hint to the comparison in Earnie. ### Version 0.+1

- [ ] **Graphical comparison of multiple tariffs without consumption** *(scope extended by the dogfooding findings of 2026-10-28)*
  - Selection: "My tariffs" become selectable, so several tariffs show in the price preview at once; only one tariff stays open for editing
  - Time span: tariffs that differ by weekday switch the preview to a time axis over the days instead of 0–24 h; when only workday, Saturday and Sunday differ, Friday to Sunday is enough, otherwise a whole week. A market-price tariff needs one day. With several tariffs the widest span of all wins. A tariff with a holiday rule gets a fictitious holiday appended after Sunday
